## 0. 结论先行

1. **目标形态**：冷路径离线构建版本化 **UI Atlas**；热路径由**单写者常驻 worker**执行“一次观测定页+定位 → 安全门 → 单次注入 → 后置校验”；失败走**分级恢复**；全程写**无正文 journal**。核心不是“更快的截图”，而是把固定开销从热路径拿掉，同时不拿掉 R2 的校验。
2. **最大三个收益**（按顺序）：单写者常驻 worker + 锁；发送事务（前置身份/内容 + 后置条件 + journal）；Atlas + 一次观测多用 + 唯一匹配。三者都不依赖 OCR 精度。
3. **最大 blocker 是 R2 身份锚点**：当前没有证据表明 App 向 `uiautomator` 暴露稳定的会话/联系人 id。**FINAL 裁决：身份无法独立证明时，R2 默认中止 + 人工确认；不允许“标题看起来对”就发送。** 这不是性能取舍，是发错人的风险。
4. **C0 ≤300ms 与 C1 ≤1.5s 是条件目标，不是承诺**：C0 成立要求 dump p50 ≤80–100ms；C1 成立要求 P0 全落地、S2 不走 OCR、中文输入成本可接受。任一不成立，必须按 §4.4 重定包络，不能静默保留数字。
5. **当前工具链没有强制单写者**：`device.py` 只调 `adb-remote.sh connect`，不持锁；两个进程可同时注入。**这是实现前的 P0 级安全缺口**，必须先补，再谈并发/宏/流水线。
6. **如果只能先做三件**：① 单写者 worker + 锁；② R2 发送事务 + journal + 后置校验；③ Atlas + 一次观测 + 唯一匹配。其余全部排在后面。

## 2. 目标架构

```text
事件/任务
  │
  ▼
S0  队列 + 事务组装（risk=R0/R1/R2/R3，idempotency_key，deadline）
  │
  ├─────────────── 冷路径（离线，不在热路径） ───────────────┐
  │  UI Atlas Builder: 页面/状态、锚点、ROI、目标三层坐标、       │
  │  hard/soft 指纹、转移表 → AtlasHandle（版本化、可失效）      │
  └───────────────────────────┬───────────────────────────────┘
                              │ 加载/校验 sha
                              ▼
             ┌─────────────────────────────────────┐
             │ 常驻 adb-worker（唯一 ADB 会话/唯一锁） │
             │  ├ job queue (FIFO)                  │
             │  ├ injection lease (1)               │
             │  ├ journal (append-only, 无正文)      │
             │  └ health / yield / dry-run          │
             └───────────────┬─────────────────────┘
                             │
   S1 观测 ─▶ S2 解析 ─▶ S3 安全门 ─▶ S4 注入 ─▶ S5 后置校验
    FrameContext  PageGuess   TapPlan    单次 tap     postcondition
    + anchors     + candidates  reject?   串行         失败 → S6
                             │
                             ▼
                  S6 失败分类 → T0/T1/T2/T3（T4 人工）
                             │
                             ▼
                  journal + telemetry（hash/耗时/计数，无正文）
```

### 2.1 分层

| 层 | 职责 | 关键约束 |
|---|---|---|
| L0 设备/传输 | adb server、transport、设备 | 不直接暴露给业务；不允许多进程注入 |
| L1 worker/租约 | 唯一 ADB 会话、FIFO、注入租约、journal | 单写者；持锁 + heartbeat + `yield` |
| L2 感知 | UI Atlas、锚点探针、ROI OCR、坐标投影 | 冷建热用；热路径不重建 |
| L3 事务/安全 | 风险分级、前置断言、身份/内容校验、后置条件 | R2 双证据独立；歧义即停 |
| L4 恢复 | 失败分类、T0–T3、健康检查、对账 | T3 需 journal；T4 人工 |
| L5 证据 | journal、遥测、验收指标 | 只存 hash/长度/计数/耗时 |

### 2.2 数据流（一次 R2 发送）

1. S0：收到“回复某会话”任务，生成 `txn_id`、`idempotency_key`、deadline。
2. S1：采一次 `FrameContext`（wm/rotation/density/font/locale/theme/insets/foreground），用 Atlas 的 required+negative anchors 得 `PageGuess`；`candidates` 非空即停。
3. S2：从同一快照取 `TapPlan`（输入框、发送键、会话头）；坐标来自 Atlas 投影/缓存，不重新缩放。
4. S3：R2 安全门——身份锚点（独立观测）+ 输入内容校验 + 目标比对 + 唯一匹配；任一不满足 → `NEED_HUMAN`。
5. S4：worker 持注入租约，单次 tap/输入；R2 不重试。
6. S5：等后置条件（新气泡/发送态），超时 → `UNKNOWN_R2`，只读对账，不重发。
7. S6：按失败分类进入 T0–T3；恢复后先 RECONCILE，再消费新事件。
8. L5：写 journal 终态与各阶段耗时。

### 2.3 四条设计规则

1. **assert-then-act**：每步先验证前置；已满足就 SKIP；动作后立即验证后置。宏不是“录制回放”。
2. **一次决策一个快照**：S1/S2/S3 看同一时刻；禁止“截图定页 + dump 定位”拼出跨时刻结论。
3. **只预测观测，不预测动作**：预取模板/锚点/ROI 可以；预点击/预输入/预发送禁止。
4. **R2 的定位证据与授权证据必须独立**：同一次 dump 既定位又“证明身份”不满足。

## 3. 冷路径、热路径、恢复路径

### 3.1 冷路径：UI Atlas（离线）

产物是一份版本化、可失效、可被 worker 消费的 Atlas，不是截图集：

- **页面/状态**：page ≤20，state ≤6/page；页面与状态分开计数（键盘、弹窗、搜索中间态不占 page 名额）。
- **锚点**：每页 required + negative；选稳定性、唯一性、可见性、探测成本都合格的节点；歧义页必须靠 negative 或第二锚点消歧。
- **ROI/模板**：只给需要 OCR/模板的局部；全屏 OCR 不进热路径。
- **目标三层坐标**：`edge+offset_dp`（跨分辨率主表示）、`px`（同 profile 精确）、`norm`（最后备选，不单独用于 R1/R2）；坐标系明确 device/screenshot/natural。
- **指纹**：`hard`（versionCode、wm、density、font_scale、locale、theme、rotation）、`soft`（每页 UI 层级/锚点集合 hash）、`pixel`（只用于标定/漂移排查）。hard 只证明环境兼容，**不证明页面身份**。
- **版本化**：`AtlasHandle{atlas_id, schema, content_sha256, app, device_profile, index}`；加载时校验 sha，不匹配拒绝加载，走 L4 慢路径。
- **构建 gate**：每页 ≥1 required anchor；required anchor 本页唯一且跨页不冲突（或有 negative 消歧）；R2 目标有身份+内容+后置校验；无私有正文；回放准确率达标；有 kill switch。

### 3.2 热路径：S1–S5

| 级别 | 观测 | 触发 | 安全边界 |
|---|---|---|---|
| L0 hard 指纹 | 批量读环境 | 每事务开始 | 只证明环境没变，不证明页面 |
| L1 连续性 | 零观测 | 刚成功注入、非身份转移、TTL ≤300ms | **仅 R0/R1**；R2 禁用 |
| L2 锚点 | 一次 dump 或 screenshot-ROI | L1 不满足 | 唯一页才继续 |
| L3 小 ROI OCR | ROI 级 OCR | L2 无锚点/文本唯一信号 | 必须位置交叉校验 |
| L4 完整 dump | 全树 + 多锚点/ROI | L3 失败/歧义 | 仍要求唯一匹配 |
| L5 中止 | 无安全观测 | 以上都失败 | 不注入；R2 → NEED_HUMAN |

OCR 的位置：冷路径用于建 Atlas（标定目标/锚点文本），热路径只在小 ROI、锚点/控件树不足时使用；缓存键含 `page_id + ROI + 预处理版本 + atlas content_sha256`，TTL 只用于 R0/R1；R2 不复用过期 OCR。文字与坐标必须来自同一次观测或两次独立观测的交叉校验，避免“文字对但位置错”。

坐标漂移：状态栏/导航栏/键盘/弹窗/旋转/分屏/字体缩放都通过 `FrameContext.insets` 与 hard 指纹处理；insets 解析失败必须拒点，不得“按经验补一个值”。`ui_coords` 的越界/零面积检查保留为最后防线，但它是**条件性**的（几何读不到时会跳过），Atlas 投影必须自己再查。另外，`ui_coords.py` 的 CLI 在不传 `--wm-size` 且不加 `--no-adb` 时默认会查 ADB（至少两次 shell），冷路径必须显式传几何，不能把它当纯离线计算。

### 3.3 恢复路径：S6 → T0–T3

失败先分类，再选最低档恢复；具体见 §7。恢复期间只读观测、写 journal、排队新事件；不插队注入，不重放已注入的 R2 步骤。

### 3.4 明确不在热路径做

- 重建 Atlas（只标 stale + 提交离线重建）。
- 全屏 OCR。
- `am force-stop`（除非 T3 且 journal 已落盘）。
- 多事务交错注入。
- 用预测结果直接做 S5 证据。

## 4. 端到端延迟预算（`TARGET`，非实测）

### 4.1 口径

- 主指标 `T_complete`：触发 → 后置条件验证。`T_react` 只作为辅助。
- 阶段名固定为 `S0…S6`；S6 在 p50 计 0，p95 计一次恢复，不藏进“其他”。
- 预算前提：P0 已落地（单写者 worker、连续性、批量 dump、事务 journal、条件等待）；未落地时不给“现状毫秒数”，因为没实测。

### 4.2 分阶段预算

| 阶段 | C0 L1（连续性） | C0 L2（新鲜 dump） | C1（无 OCR） | C1（ROI OCR） | C2 T2 | C2 T3 |
|---|---:|---:|---:|---:|---:|---:|
| S0 触发/排队 | 5 | 5 | 5 | 5 | 0 | 0 |
| S1 状态判定 | 5 | 80 | 60 | 60 | 400 | 400 |
| S2 识别 | 5 | 5 | 60 | 180 | 0 | 0 |
| S3 决策/安全门 | 10 | 10 | 40 | 40 | 100 | 100 |
| S4 输入注入 | 55 | 55 | 80 | 80 | 1500 | 4500 |
| S5 后置校验 | 130 | 130 | 600 | 600 | 1500 | 1500 |
| S6 恢复（摊销） | 0 | 0 | 0 | 0 | 0 | 1000 |
| **合计 p50** | **210** | **285** | **845** | **965** | **3500** | **7500** |
| brief 包络 | ≤300 | ≤300 | ≤1500 | ≤1500 | ≤8000 | ≤8000 |

p95 组成（`TARGET`）：C0 ≈800ms（重探 250 + 重试 200 + 队列 60）；C1 ≈4000ms（S5 长尾 1500 + 一次重试 1200 + 队列 400）；C2 ≈20000ms（T2 失败 3.5s + T3 7.5s + 对账 9s）。

### 4.3 哪些能省、哪些不能

- **可省**：S2 在坐标缓存命中时≈0；L1 连续性命中时 S1≈0（仅 R0/R1）；S2 与 S1 可共享同一次 dump；S5 期间可预取下一页模板（只读）。
- **不可省**：S3 安全门（R2 身份+内容）、S5 后置校验、S4 单写者串行。
- **不可并行**：注入；同一决策的截图+dump 各算一次；R0 与 R2 混批。

### 4.4 破包络时的裁决规则

1. 实测 dump p50 >100ms → C0 不再承诺 300ms；二选一：**放宽到 400–600ms**，或**投入 P1-5 常驻 UI agent**。不得把 150–300ms 的 dump 仍写成 300ms。
2. C1 若因中文输入/OCR 超出 1.5s → 标 `UNVERIFIED`，先做“草稿 + 人工确认发送”，不硬凑数字。
3. 任何阶段超预算，先砍“可省”项，再降级，不得砍 R2 校验。

## 5. 分阶段落地顺序

### 5.1 如果只能做三件

1. **P0-1 单写者常驻 worker + `adb-remote` 锁 + `yield` + dry-run**。
2. **P0-2 R2 发送事务：前置身份/内容 + 后置条件 + journal + 幂等**。
3. **P0-3/P0-4 Atlas v1 + 一次观测定页/定位 + 唯一匹配/歧义即停**。

理由：没有 1，任何并发都是错点风险；没有 2，发送不可对账、T3 不合法；没有 3，热路径仍然每步全量 dump，且重复匹配会点错。

### 5.2 P0（先做，缺一不可）

| ID | 内容 | 依赖 | 完成判据 | 主要风险 |
|---|---|---|---|---|
| P0-1 | 常驻 worker，唯一 ADB 会话、唯一注入租约、`adb-remote.sh acquire/heartbeat`、`yield`、全局 dry-run | 无 | 两个并发客户端提交 tap，只有一个执行；worker 挂后锁可回收 | 持锁把人工调试锁死；需 yield |
| P0-2 | 事务器 + journal + 幂等键 + R2 后置条件 + RECONCILE | P0-1 | 崩溃后不重发；`UNKNOWN_R2` 只对账；journal 无正文 | 后置条件选错 → 假成功 |
| P0-3 | Atlas v1：页面/状态、锚点、三层坐标、hard/soft 指纹、转移表 | 可与 P0-1 并行 | 20 页内可加载；sha 不符拒绝；R2 目标有校验 | 页面/锚点未经真机盘点 |
| P0-4 | 一次观测定页+定位；`PageGuess.candidates`/`TapPlan.reject` 非空即停；R1/R2 唯一匹配 | P0-3 | 构造重复 text/id，返回 Ambiguous；不回退 index=0 | 合法重复控件被拒 |
| P0-5 | 有界连续性 L1（≤300ms，仅 R0/R1）+ 失效事件 | P0-1/P0-3 | 注入/前台/IME/滚动/版本变化后立即失效 | 人手接管检测不到 |
| P0-6 | dump 单往返（`sh -c` 批量或等价）+ 0.5s 固定轮询改条件等待 | P0-1 | 同页 dump 宿主往返减少；p50 量化损失下降 | 半截 XML；轮询过密 |
| P0-7 | 降级阶梯 L0–L5 + kill switch | P0-3 | 断网/无锚点/歧义均能停在安全级别 | 降级死循环 |

VISION 的 P-V1/V2/V3/V4/V7 分别落在 P0-3/P0-4/P0-7；P-V6 落在 P0-5；P-V8 是 P0 的**门**，实现放 P1-3。

### 5.3 P1（P0 之后，按需）

| ID | 内容 | 依赖 | 说明 |
|---|---|---|---|

## 6. 一键宏：事务、幂等、回滚

### 6.1 粒度

- 单步 tap：只作为事务内部单元，不单独暴露给外部。
- 页面级：R0/R1 的默认粒度（边界清晰、前后置好写）。
- 事务级：R2 的唯一粒度（“校验会话→输入→发送→确认”）；幂等键、对账、证据都在事务层。
- **不采用录制回放**：按时间戳回放点击序列没有断言、没有幂等、对布局漂移零抵抗。

### 6.2 状态机（摘要）

`PENDING → RUNNING → (ASSERT 前置 → 已满足 SKIP / 不满足 ACT → VERIFY 后置) → COMMITTED`；可判定失败 → `FAILED_RETRYABLE`（R2 不允许）；注入后结果不明 → `UNKNOWN_R2`（只读对账 → COMMITTED / NEED_HUMAN）；崩溃 → `ORPHANED`（启动读 journal → RECONCILE，只读，不重发）。

### 6.3 幂等与回滚

- 幂等不是“给点击编号”，而是**让每步在已完成后可被前置条件识别并跳过**；点击本身没有幂等性。
- `txn_id` 用 ULID；`idempotency_key = sha256(txn_id:step.seq:intent_hash)`；R0/R1 有终态可返回上次结果；R2 重复提交**拒绝**，返回终态或 NEED_HUMAN。
- 回滚：打开页面/输入草稿/选择会话可自动回退并复验；发送（R2）**无回滚**，只能对账+上报；重启在阶梯内回退或停机。

### 6.4 证据格式

journal 只允许：页面 id、动作类型、坐标 hash、锚点/文本 hash、长度、计数、耗时、错误类；journal 终态与各阶段耗时供 p50/p95。禁止消息正文、会话名、截图、XML 片段、token。

## 7. 快速重启分级

“重启应用”按钮 = 执行阶梯，停在第一个恢复成功的档位，并展示档位/耗时/验证证据；不是无条件 force-stop。

| 档 | 重启对象 | 触发 | 动作 | 验证 | 回退 | 在途任务 | `TARGET` p50 |
|---|---|---|---|---|---|---|---|
| T0 | ADB transport | offline/缺行/exec-out 连败 | disconnect + connect（worker 状态机） | `getprop` + `pidof` | 重试 2 次 → T1 | 未注入，无需持久化 | ≤1.5s |
| T1 | worker | 心跳丢失/job 卡死/锁冲突 | 重启 worker，App 不动 | 健康端点 + 只读探针 | → T2 | journal 在盘，启动 RECONCILE | ≤2s |
| T2 | Activity | 前台不对但进程在/页面卡死/导航栈乱 | `am start -n pkg/.MainActivity`（**不** force-stop） | 同 pid + 前台包名 + 目标页锚点 | → T3 | 事务状态保留 | ≤2s |
| T3 | App 进程 | T2 后仍 ANR/崩溃/白屏/pid 消失 | `am force-stop` + `am start -W` | 新 pid + 前台 + 锚点 + FATAL/ANR 计数 | 停机/上报 | **必须先 journal**；启动对账 | ≤5s |
| T4 | 设备 | T3 连续失败/系统级卡死 | `adb reboot` | 开机 + adb + app + 锚点 | 人工 | 全部落盘，人工确认 | 默认不做 |

约束：

- **默认 T2**；T3 以 P0-2 journal 为前置；之前“重启按钮”最高 T2。
- `am start -W` 只表示启动完成，不代表页面就绪；T2/T3 验证必须含锚点。
- 单任务重启预算：T0×2 + T1×1 + T2×1 + T3×1；超预算 → `NEED_HUMAN`，避免重启风暴。
- 恢复期间新事件只排队；恢复后先 RECONCILE，再按序消费；不重放已注入的 R2 步骤。

## 8. 安全边界

| brief §6 不变量 | FINAL 机制 | 失败行为 |
|---|---|---|
| 1 单写者 | worker 唯一注入租约 + `adb-remote.sh acquire/heartbeat`；任何外部进程不得直接 `adb input` | 拿不到锁 → 排队/拒绝 |
| 2 发送双校验 | S3：独立身份锚点 + 输入内容 hash + 目标比对 + 唯一匹配 | 任一不符 → 中止 + NEED_HUMAN |
| 3 不可逆后置校验 | R2 必须 `postcondition_required`；S5 超时 = 失败 | 不算成功，不重发 |
| 4 幂等 | txn/step 幂等键 + journal 终态 + 崩溃 RECONCILE | 重复提交被拒 |
| 5 重启不丢任务 | journal 先写后 force-stop；启动即对账 | 无 journal → 禁止 T3 |
| 6 坐标安全 | `EmptyNode`/`OutOfBounds`/`NodeNotFound`；Atlas 投影自检；不回退 `(0,0)` | 报错即停 |
| 7 证据不泄密 | journal 只存 hash/长度/计数；截图不落仓库；dump 写仓库强制脱敏 | 写前拒绝/脱敏 |
| 8 可关闭 | `atlas.enabled=false`、worker dry-run、`yield`、宏级 kill switch | 关闭后只走只读/慢路径 |

额外硬规则：

- **R2 身份无法独立证明 → 中止 + 人工**；标题 OCR/头像/纯坐标都不能单独授权发送。
- **R1/R2 重复匹配 → Ambiguous**；`select_node` 的 `index=0` 默认值不得作为回退。
- **边界检查是条件性的**：`ui_coords` 几何读不到时会跳过越界校验；Atlas 投影必须自己再查。
- **不预测动作**；预测产物不得作为 S5 证据。
- 任何“去掉/弱化 R2 校验会更快”的提案，结论是拒绝，不进入排序。
