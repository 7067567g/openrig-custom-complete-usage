# FINAL — g3d overlay：两种身份的全流程、使用模式与稳定度

- 合并：`pair-1/SIMULATION.md`（轻量体验者 A/B）+ `pair-2/SIMULATION.md`（开发者/重度创作者 C/D），并以两对 Turn 3 评审（`pair-1/B.md` 的 Turn 3、`pair-2/D.md` 的 Turn 3）做最后校正。
- 性质：**使用模拟 + 设计推演 + 待验证协议**。没有运行产品、没有真机、没有真实用户、没有 fixture、没有跑实现。
- 读法：本文所有“系统响应”除注明外，都是**应然目标**或**依据 CONTEXT 建议架构的行为假设**，不是产品现状；所有数字都是【目标】/【待校准】/【推断】，不是实测。本文的“PASS”只可能指文档交付验收（见 `ACCEPTANCE.md`），**不指产品稳定度通过**。

## 0. 结论摘要

1. **两种身份的共同瓶颈不是渲染，是状态。** 轻量作者卡在“改内容=白摆、重发=旧链接”；开发者卡在“重开/切投影/休眠后相机与内容回不来”。两边最后都退回截图交付。共同根因是资产、实例、GPU、快照四层没有分开。
2. **轻量身份的第一道门是入口，最大概率失败是观看者以为“就一张图”，最大代价是存不到干净图。** 对应 S2、V2、V5；不是模型精度。
3. **开发者身份的分水岭是“两次打开能否复现同一视角与构图”。** 导入 18MB GLB 不是分水岭；保存/重开、AI 编辑、分享端三处任一断，功能就降为一次性演示。
4. **v1 默认值只能服务一个主模式：讲解/审阅都要“静止在书签”。** 默认 auto-rotate 同时服务编辑、讲解、审阅、展台四个场景的假设不成立；观看端自动旋转在 v1 砍掉，只留 P1 实验。
5. **预算必须从“单项上限”升级为“同一时刻峰值 + 准入 + 滞回”。** 逐项合规仍会 OOM；30 万/40 万双硬线必须收成一个；全屏 3D canvas + DPR 1.5 在 2K/4K 画布上不成立，必须裁到活跃 overlay 并集或反算 DPR。
6. **交付不是“一个 URL”，是“卡面 + 首帧 + 能转的入口 + 可存图”。** 封面固定 3/4、1:1 先算 fit、不可变快照、share poster、能力探测、只读锁，缺一项就会退回截图。
7. **选中、改名、封面三处语义必须收敛。** 选中要有非空间入口（图层列表/4px 轮廓），不能“名字条只在选中时出现、又靠点名字条选中”；v1 砍内联改名与作者自定义封面。
8. **V2（打开后以为是一张图）没有被解决，只是有了可测的发现手段。** 在 H22/H28 完成前，FINAL 只写“已增加卡面角标、观看页 ghost hand、常驻 `↻` chip，待验证”，不写“已修”。
9. **本轮的证据是 0 条实测。** 所有 R1–R4、S6/S9/S10、预算数字、fps、内存、微信白屏都保持 `UNOBSERVED`；未验证不等于通过，也不等于已失败。

### 1.3 产品/环境假设（未验证，按条对待）

- **入口与默认值**：入口在右键/插入菜单；首次插入有示例；新 overlay 落视口中心；默认 auto-rotate 开；边中点做非等比拉伸。
- **状态与恢复**：相机不持久化、只存位置尺寸；无 runtime poster；无四类生命周期事件；context lost 只能重开 app；AI 编辑原地替换且重置相机。
- **交付**：分享链接无需登录、是快照；分享端无 poster、无能力探测；旧链接与新版同貌；og 缓存不可控。
- **格式与预算**：只有单文件 20MB 提示；预处理一次性、不可取消；`g3d` 只存场景图；源文件只读一次。
- **用户**：轻量作者会在 45 分钟内放弃微调；开发者会自救但不应被当成产品方案；8–12 个是“摆着”还是“同时看”未知。
- **语义歧义**：CONTEXT 的“8 向手柄移动 / 等比缩放”可能是“8 方向移动 + 等比缩放”，也可能是“8 个缩放手柄 + 等比缩放”；本 FINAL 按后者推演，但把它列为 H9 待产品一句话确认。

### 1.4 明确不宣称

- 不宣称微信一定白屏/一定可用、og 一定不刷新、X5 一定有问题。
- 不宣称用户一定把名字条读成标题、一定按 Cmd+Z、一定在 10 秒内转。
- 不宣称“修复后会通过”；S6/S9/S10 的 8/8、1s、10s 都是验收假设。
- 不宣称 8 个 overlay 同时流畅、2D 夹层可行、RT+Konva 可行、两条 3D 层不值得。
- 不宣称 AI 生成质量可达 70 分；H27 未测前，生成质量是最大未验证变量。

### 2.3 两种身份的共同点与差异

- **共同点**：都要“两次打开是同一个东西”；都被相机/版本/内容丢失伤到；都不需要高画质/CAD/编辑器。
- **差异**：轻量作者要“发得像样、存得下、说得清”，开发者要“讲得准、切得稳、恢复得快”。前者怕入口与卡面，后者怕预算与生命周期。
- **不可合并**：轻量侧的 5 人测试不能替代开发者真机；开发者的自救不能替代轻量侧的可发现性。

### 4.2 模式裁决

- **成立且进 v1**：摆放/编辑（2 个）、分享交付、观看审阅、返工/版本、开发者讲解、故障恢复、降级审阅。

- **不成立/砍**：8 个同时转、多人实时协作编辑、高画质/CAD 级审阅、教学/剖切/正交/真实尺寸、观看端自动旋转、内联改名、作者自定义封面。

## 5. 稳定度 / 限制

### 5.1 三层状态 + 快照：先定字段，再谈 UI

| 层 | 字段 | 持久化 | 谁可以改 |
|---|---|---|---|
| asset | `assetId`、`assetVersion`、`derivedFrom`、`refCount`、`srcHash`、`g3dKey`、`pipelineVersion`、`params`、`textureFormat`、`budget`、`recommendedCamera` | 是（缓存/资产库） | 重新预处理；显式“应用到所有引用”的素材编辑 |
| instance | `ovId`、`assetId`、`assetVersion`、`camera`、`cameraSource(recommended/user/ai)`、`cameraHash`、`transform`、`visible`、`autoRotateOverride`、`layerRole`、`lock`、`dim`、`bookmarkPosterKey`、`lastFrameKey`、`lastGoodFrameAt`、`degradedReason`、`versionRef` | 是（画布文档） | 用户拖拽/缩放/书签；AI 实例编辑；版本切换 |
| GPU | geometry、texture、material、program、render target；`resourceEpoch`、`needsRebuild`、`contextState` | 否（可随时丢） | 渲染器；从 instance + asset 重建 |
| snapshot | `snapshotId`、`assetId + assetVersion` 集合、`camera` 集合、layout、cover、createdAt、`schemaVersion` | 是（不可变） | 发布时冻结；旧链接只读 |

**不变量**：

1. 相机/变换只存实例态；`g3d` 只存 `recommendedCamera`。同一 GLB 两个实例，各自相机，互不污染。
2. 任何重建/恢复路径都**不重置 camera/transform**；例外只有用户显式“重新取景”。
3. `assetVersion` 切换默认保留当前相机；只有包围盒变化超过阈值（建议 20%【待校准】）才提示“新版本构图可能不同：保留视角 / 自动取景”，默认保留。
4. 每次重建 `resourceEpoch++`；所有异步回调带 epoch 校验，不匹配就丢弃，避免“恢复后闪回旧画面”。
5. 快照不可变：同一 `snapshotId` 永远指向同一 assetVersion + camera + layout；发布新版本 = 新 snapshot + 新 URL；旧链接不“原地变新”。

### 5.2 实例 / 三角形 / 格式 / 大小预算（全部待校准）

| 维度 | 舒适 | 降级（自动 + 提示） | 硬拒绝 / 强制 | 性质与备注 |
|---|---|---|---|---|
| 画布内总数 | ≤8 | 9–12 | >12 | 用户可摆 ≠ 同时渲染；轻量侧 v1 只测到 2 |
| 同时活跃 | ≤3 | 4–6 | >6 需手动激活 | 活跃集合 = 用户 pin ∪ 焦点 ∪ 视口内且 30 秒内交互过；单个活跃需有 GPU 资源且可接受输入；warm 激活 ≤300ms |
| 单 overlay 三角 | ≤5 万 | 5–15 万 | >15 万 | 单模型准入 |
| 同屏活跃三角 | ≤15 万 | 15–30 万 | >30 万 | **只留 30 万，不再并存 40 万**；3×5=15 万才与活跃数自洽 |
| 聚合纹理 | ≤120MB | 120–240MB | >240MB 强制 poster | `Σ(w×h×4×4/3)`；2048²≈22.4MB/张 |
| drawing buffer | ≤4M px | 4–6M px | >6M px 强制降 DPR/关 MSAA | 按整张画布面积；见 DPR 公式 |
| DPR | `min(1.5, sqrt(4M/stagePx))` | 降 DPR + 提示 | 按硬线反算 | 全屏 3D canvas + DPR1.5 在 2K/4K 不成立；必须裁到活跃并集 |
| draw calls / overlay | ≤100 | 100–250 | >250 | 100 节点×500 面可能更慢；与三角并列 |
| overdraw | ≤2× | 2–3× | >3× | 透明叠加是填充率大头 |
| 单 g3d 字节 | ≤8MB | 8–20MB | >20MB | **输出合规，不看源文件** |
| 源文件 | ≤80MB 预警 | 80–200MB 慢/提示 | >200MB 或解析 >30s | 只作成本/超时预警，不作输出合规依据 |
| 单贴图边长 | ≤1024 | 1024–2048 | >2048 且降采样失败 | 加聚合纹理预算后才完整 |
| 估算显存 | ≤200MB | 200–320MB | >320MB 强制降级 | **只作顾问值**；硬拒绝不靠它 |
| 帧时间 p95 | ≤1.25×刷新周期 | 1.25–1.67× | >1.67× 强制降级 | 用 missed vsync，不用平均 fps |
| runtime poster | ≤1s | 1–3s | >3s 判恢复失败 | 从失效首帧到非空 poster；**warm 目标** |
| 激活延迟 | 视觉反馈 ≤100ms | 可交互 ≤300ms（warm） | >1s（cold）判失败 | 可交互 = 拖拽有响应 |
| 版本存储 / 文档 | ≤200MB 磁盘 | 200–500MB | >500MB 提示清理/仅留 1 版 | 内容寻址 + `refCount` + LRU；**磁盘配额，不计入运行峰值** |
| 分享文档 | ≤25MB | 25–40MB 降展示档 | >40MB 或 4G 首屏 >5s 强制 poster-only | `manifest + Σ展示档 + Σposter`；25MB 待产品定 |
| **同一时刻峰值** | ≤300MB | 300–400MB | >400MB 强制降级/拒绝 | `peakBytes = buffer + Σ可见纹理 + geometry + Σ可见 poster 解码 + 常驻版本缓存`；新增硬线，优先于单项表 |

**公式**：

```text
texBytes(t)        = w * h * 4 * 4/3          # RGBA8 + mip
aggregateTexture   = Σ over overlays Σ over textures texBytes
bufferPx           = canvasW * canvasH * dpr²
bufferBytes        ≈ bufferPx * 8              # RGBA8 + depth24stencil8
dprMax             = min(1.5, sqrt(maxBufferPx / (canvasW * canvasH)))
overdraw           ≈ Σ(area_i * innerLayers_i) / viewportArea
peakBytes          ≈ bufferBytes + Σ可见纹理 + geometry + Σ可见poster解码 + 常驻版本缓存
shareBytes         ≈ manifest + Σ referencedG3D + Σ posterBytes
versionBytes       ≈ Σ uniqueBlob(assetVersion)   # 内容寻址后
```

**算例（【推断】，只说明量级）**：

- 2048² RGBA8 单张 ≈16.8MB，含 mip ≈22.4MB；8 overlay×3 张 ≈**537MB**；全降 1024² ≈**134MB**。
- 2400×1400@DPR1.5 = 7.56M px；RGBA8+depth24stencil8 ≈**60MB**；4K@DPR1.5 = 18.66M px ≈**149MB**；4×MSAA 颜色缓冲约 4×。
- 4K/DPR1.5 硬配置：buffer 149MB + 聚合纹理 240MB + 几何约 29MB + 可见 poster 约 50MB ≈**468MB**，越过 400MB 硬线；即使纹理 120MB 也约**348MB**。
- 8×8MB 展示档 + 24 张 0.5MB poster ≈**76MB**；4G 首屏会很难看。
- poster 解码 75MB 只在 16:9/长边 2048 成立；4:3 约 100MB，方形约 134MB；**按 4:3 最坏值算，只解码可见 ≤3 张，离屏立即释放**。

### 5.3 上下文丢失与恢复

| 事件 | 识别 | 动作 | 保留 | UI |
|---|---|---|---|---|
| `resize`（含 DPR） | canvas/DPR 变化 | 重建 drawing buffer，保留资源；失败降 DPR，**不重建场景** | camera/transform | 无感，或状态栏“已降 DPR” |
| `context lost` | `webglcontextlost` / `isContextLost()` | 冻结该 context 的所有 viewport，显示 runtime poster，`epoch++`，逐个/整场景重建 | 文档态 | poster + “恢复中” |
| `context restored` | `webglcontextrestored` | 校验 epoch，丢弃旧回调，按 poster → g3d 缓存 → GPU 上传 → 交互 重建 | camera/transform | “已恢复” |
| `visibilitychange` | 文档隐藏/显示 | 暂停 render loop，离屏 overlay 冻结；恢复时只重建脏的 | 文档态 | 无 |
| `suspend/resume` | `powerMonitor`（主进程） | 先探测 `isContextLost()`，再决定重建范围 | 文档态 | 唤醒后 poster/重建 |
| 重建失败 ≥3 次 | 计数器 | 进入 `failed`，给失败卡：重试 / 用 poster 继续 / 重新定位源文件 / 降低预算 | 文档态 | 失败卡，不空白 |

**单 overlay 状态机**：`pending → preprocessing → ready → degraded(poster/lowres/lowdpr) → failed(reason) → disposed`，另加 `restoring`。每个状态都要有可见表现；删除必须同步 `dispose`；undo 栈只存文档态与 g3d 引用，不存 GPU buffer。

**poster 的硬规则（D Turn 3 M2 的修正）**：

- `runtimePoster` 在 ready/书签/版本切换时生成，保存**捕获时的相机快照** + `posterSource={assetVersion, cameraHashAtCapture, renderSettings}`；**不要**用 live `cameraHash` 判过期，否则用户一转，poster 立刻 stale，context lost 时又无法重生成。
- 恢复时先显示 last good poster，并标注“上一个可用视角”；不要在 1 秒内假装它就是当前视角。
- **cold 没有 poster 是正常的**：cold 的 1 秒目标不成立，只能给 share poster/骨架 + ≤10 秒可交互；`1s` 只写 warm。
- **`lastFrame` 必须是 DOM `<img>` / ImageBitmap / 2D canvas，不能是 WebGL texture/FBO**；否则 context lost 时 poster 跟 context 一起没。`lastFrame` 存文档（8 张 ×≤500KB ≈4MB 可接受），ready + settle 500ms + 版本切换时更新；恢复顺序：显示 `lastFrame` → 重建 → 应用 instance camera → 角度差 >15° 时一行说明。
- `bookmarkPoster` 与 `lastFrame` 分开：前者严格绑书签、用于分享；后者不按 live `cameraHash` 判 stale。不要用一个 poster 同时承担“恢复”和“分享”。
- 降级后可升级：滞回 + 每次降级 3 秒冷却 + 连续 2 次才升级，避免糊/清震荡；拖动中不升级。
- 准入的两个坑必须写死：`demote(LRU)` 排除刚激活的候选 `v`；`active.size == 1` 时先把旧重模型转 poster，再接纳用户刚点的 `v`，不能直接拒绝新模型。
- 单 context + scissor 的 context lost 是**全局故障域**；不要写成“单 overlay 隔离”。整层 lost 用整层失败卡 + 每个 overlay 的 poster；单 overlay 资源/解码失败才用单卡。per-overlay RT 只进 spike，未验证前不宣称。

| # | 触发 | 用户看到 | 后果 | 修复 | 状态 |
|---|---|---|---|---|---|

| F-TERMS | “活跃/可交互/一致/通过”没定义 | 测试各取所需 | 假通过/假失败 | 活跃=pin∪焦点∪视口内 30s 内交互过；可交互=全分辨率首帧+拖拽 100ms 内响应+相机未重置；一致=同 `cameraHash`，不能导出时只写“视觉一致”；R3 拆 R3a 静态交付 / R3b 预算内可交互，R3b 不允许仅 poster 通过 | 验收规则 |

| F-LINK | og 缓存/旧卡片同貌 | 群里点旧链接 | 返工白做 | 唯一 URL + 卡面 `v4`/时间；og 刷新列为外部依赖 | 外部依赖 |
| F-READONLY | 只读端仍可编辑/改变换 | 客户误改作者布局 | 交付不可信 | 只读锁：不可选中/不可变换/不可 AI 编辑 | 设计决定 |

**“不允许静默”清单**：任何相机重置；任何“有内容→空白/灰块”；任何降级无角标/原因/恢复入口；任何 AI 改变作用域或相机而无单独确认；任何 poster 为空；任何 `assetVersion` 切换相机未迁移；任何分享端自动播放把书签转走；任何峰值/热降频降级不写原因；任何降级后无法恢复；任何 poster 与实时画面明显不一致；任何跨设备降级档位不同。

### 5.5 测量有效性与限制

- **固定**：窗口尺寸、`devicePixelRatio`、刷新率、电源模式、热稳态；截图/录屏前关 auto-rotate 与所有动画，等 3 帧稳定。
- **帧率不取平均**：记录 10 秒内 `missedVsync` 数、帧时间 p50/p95、最长帧；30Hz 下 24fps 不是稳定状态，只有 30/15/10 三档。
- **时间用帧号**：失效首帧 / poster 首帧 / 拖拽有响应首帧；60Hz ±16.7ms、30Hz ±33ms，阈值留误差。
- **每条结论带 `runManifest`**：build hash、OS/GPU/驱动、显示器/DPI/刷新率、fixture hash、缓存状态、电源模式、测试人。
- **不可观测就写 `UNOBSERVED`**：VRAM、dispose、context lost 计数、GPU 进程是否被杀；**未验证不等于通过，也不等于已失败**。
- **截图对比**：固定窗口/DPR/关闭动画/同一帧号/同一 mask；camera 不能导出时只写“视觉一致”，不写 ≤2°。
- **本模拟的限制**：没有 fixture、没有真机、没有用户；所有时间/内存/帧率/显存数字不可引用为实测；产品现状未知，“现状假设”可能全错。

## 6. 产品含义

> 这里的“MVP 必做”是**发布地板**，不是功能愿望清单。每条都要能对应一个失败模式；对应不上的，进 nice-to-have 或砍。

### 6.1 MVP 必做（P0）

1. **入口 + 命名 + 一次演示 + 生成态。**
   - 入口在“图片”旁，只叫“3D 模型”；禁用“叠加/overlay/场景图/Beta”。
   - 首次插入：2 秒 ghost hand（触控板/鼠标 click-drag，触屏单指横拖）+ 名字条 ✥ 区高亮一次；不靠 16 字说明。
   - 生成态：预计秒数 + “可离开此页” + 完成通知 + 失败原因 + 重试/换描述；切走不取消，回来不重复提交。
   - 判据：5/5 在 30 秒内转起来，不读说明；生成中离开再回来不重复提交。

2. **实例态 schema + 四层状态。**
   - asset / instance / GPU / snapshot 四层；`camera` 只在 instance；`g3d` 只存 `recommendedCamera`。
   - `cameraHash` / `posterSource` / `resourceEpoch` / `assetVersion` / `refCount` 字段先落地；**只定字段，不做 UI**。
   - 判据：S6/S7/S9 需要恢复的每一项都能在字段里找到；找不到就不许开工生命周期。

3. **生命周期 + runtime poster + 失败卡。**
   - resize / context lost+restored / visibilitychange / suspend+resume 四条路径分开；`epoch++`；`lastFrame` 用 DOM 存文档，`bookmarkPoster` 绑书签；重建顺序 poster → g3d 缓存 → GPU 上传 → 交互。
   - 失败卡：重试 / 用 poster 继续 / 重新定位源文件 / 降低预算；**整层 context lost 用整层提示 + 每 overlay poster**，单 overlay 资源/解码失败才用单卡；不空白。
   - 判据：warm poster ≤1 秒、≤10 秒可交互、相机不变；cold 只承诺 ≤10 秒。

4. **实例态持久化。**
   - `camera / transform / visible / autoRotateOverride / 层序 / 版本指针`；warm 与 cold 分开测；书签 1 个起步。
   - 判据：8/8 一致；不能导出 camera 时只写“视觉一致”，不写 ≤2°。

5. **导入预检两段式 + 两出口 + 三阶段取消。**
   - <100ms 粗卡（格式/源大小/预计输出）；<1s 细项（三角/贴图/预算）；三阶段取消无残留；43MB 给“自动压到上限 / 我自己处理”两条路。
   - 源文件字节只做 warning/timeout；硬闸门看预计输出 + 聚合预算。
   - 判据：S2 两段式 <100ms/<1s；取消无残留；43MB 有两个出口。

6. **峰值预算 + 准入 + 滞回。**
   - `peakBytes` 400MB 硬线；30 万活跃三角硬线；聚合纹理 240MB；buffer 6M px；draw calls 250；overdraw 3×；DPR 反算；3D canvas 裁到活跃并集。
   - 准入顺序：先降级、再拒绝、最后才让用户选；每次只降一级；状态栏写具体原因；焦点只免自动降级；连续 2 次恢复失败给一键降级卡；终态“静态预览 + 手动恢复”。
   - 判据：8 摆/3 活跃 + 4–6 突发不 OOM；每次降级有原因；降级后可恢复。

7. **交互：4 角点 + 移动区 + 非空间选中。**
   - 4 角点等比；边中点不是缩放手柄；非等比只在高级数值输入（或砍）；名字条 ✥ 区 44×44 拖动；拖本体=旋转。
   - 选中三条路径：形状命中 / 4px 轮廓带 / 图层列表；名字条只在选中后出现，但图层列表始终可用；重叠用重复点击循环 + `Alt` 选下层。
   - 内联改名砍掉；改名在右侧面板“名称”。
   - 判据：60 秒完成“转+移+放大”≥4/5；重叠下层 ≤3 次点击 ≥4/5；改文字误选 ≤1/10；薄壁/镂空选中 ≥8/10（或明确降级到图层列表）。

8. **交付：封面 + 快照 + share poster + 只读。**
   - 封面固定 3/4、**先按 1:1 算 fit**、8% 留白、白底；去选中/去 chrome；96px 预览不算一步；卡面“可转”+`v4`。
   - 发布 = 新 snapshot + 新 URL；旧链接冻结；“更新”= 复制新链接，不做同一 URL 原地更新。
   - share poster 非空；能力探测；无 WebGL2 → poster 画廊；弱设备 → 单活跃；作者“预览为接收端”；只读锁不可选中/不可变换/不可 AI 编辑。
   - 判据：封面 0 决策；卡面 5/5 说出“能转”；三台设备 ≤3 秒有内容；R3 不允许仅 poster 通过“客户自己转”。

9. **观看页：默认静止 + 视角菜单 + 存图。**
   - 页面首帧先绘封面静态图；2.5 秒未出 3D 则保持静态图 + 一行“3D 加载中/当前不可用”，不能白屏。
   - 默认静止在书签；`100dvh` 不滚；底部 88px 安全带（含 `env(safe-area-inset-bottom)`）放 `视角`（封面/3/4/正面/背面，当前项高亮，含“自定义”）与 `存图`；模型 fit 在带上。
   - **v1 无自动旋转**；`prefers-reduced-motion` 下 0 自动运动；键盘 ←→/±/0/Esc。
   - 存图：白底、长边 2048 绝对像素（`2048 / bbox 长边`，不受 DPR≤1.5 限制）、底部“作者 · 时间 · 角度（人话）”；GPU/耗时不行降 1600/1440 并同步改验收。
   - 判据：10 秒转起来 ≥4/5；“以为是一张图”0/5；“想停停不下来”0/5；底部误触 0/5；存图 2 次点击、长边 ≥2048。

10. **AI：COW + cameraDiff + 坏结果不落盘。**
    - AI 编辑派生新 `assetVersion`，默认只改当前实例；camera/transform 默认保留；`cameraDiff` 单独确认；对比/采用/丢弃；校验失败不落盘。
    - 标签 billboard + 避让 + 引线；记录 `prompt/modelVersion/inputHash/cameraDiff`。
    - 判据：原版可回滚；相机不静默改；坏结果不入画布；S7 新版本不覆盖。

11. **测量与诊断。**
    - as-is / to-be 两列；每步记 `检验假设` + `PASS/FAIL/NA/UNOBSERVED` + 缺陷类型；`runManifest`；最小事件日志（状态迁移/context 事件/降级原因/重建耗时）。
    - 判据：每条结论可追溯到 run；`UNOBSERVED` 不被写成 PASS。

### 6.2 P0 验收口径（可测，不是愿望）

- **作者入口**：无辅助 ≤10 秒看到入口，5/5；S4 ≤30 秒转起来，5/5。
- **作者手势**：S4→S11 ≤60 秒完成“转+移+等比放大”，≥4/5；改文字误选 overlay ≤1/10。
- **作者改内容**：真机 5/5 位置/大小/相机不变；重发 ≤60 秒。
- **封面**：0 个作者决策；5/5 不认为封面是“特写/带框”；**v1 不写“换封面 ≤1”**（自定义封面 P1）。
- **卡面**：群聊列表里 5/5 能说出“这个能转”（只看卡片、未点开）。
- **观看者 V2**：10 秒内转起来 ≥4/5；“以为是一张图”0/5；想停停不下来 0/5。**H22/H28 未完成前，只写“已增加可测的发现手段，待验证”。**
- **观看者 V5**：2 次点击内出图；长边 ≥2048px；白底；≥3/5 愿意直接转发（不是“凑合”）。
- **底部安全带**：375px 误触 0/5；作者/版本信息可见；不显著降低“大图”感受。
- **重叠选择**：主+配重叠 50%，选中下层 ≤3 次点击，≥4/5；薄壁/镂空 ≥8/10 或明确走图层列表。
- **二次使用**：次日/隔周同作者新海报，无帮助 ≤3 分钟；≥4/5 不用问“怎么移动”（P1 观察）。
- **reduced-motion**：系统开启后 0 自动运动（可自动测）。
- **微信**：≥10 台、3 种网络，不推断。
- **恢复**：warm poster ≤1 秒、≤10 秒可交互、相机不变；cold ≤10 秒；不空白、不重置。
- **峰值**：4K/DPR1.5 场景 `peakBytes` ≤400MB；8 摆/3 活跃 30 分钟无 OOM/context lost（目标，待真机）。
- **R3**：拆 R3a（静态交付，三台设备 ≤3 秒有内容）与 R3b（预算内可交互，点模型能转且相机=书签）；若宣称“能自己转”，不能只靠 poster 通过。

### 6.6 对 g3d/v1 的建议（格式与边界）

**定位**：`g3d/v1` 是**显示用资产格式**，不是画布文档格式，也不是版本库。它只描述“这个资产长什么样、推荐怎么取景”；不描述“这个实例现在是什么角度、放在哪、选中没有”。

**建议字段（JSON 场景图 + 可选 buffer）**：

- 顶层：`formatVersion`、`assetId`、`assetVersion`、`pipelineVersion`、`sourceHash`、`units`（米）、`upAxis`、`bounds`、`validation`（三角数/贴图字节/预计 draw calls/预算报告）。
- `recommendedCamera`：`position`、`target`、`fov`、`near`、`far`；**只作推荐**，消费端没有就用 `bounds` fit；`assetVersion` 切换默认保留实例相机，不读这个字段覆盖。
- `nodes`：图元/网格/标签；`materials`：最小 PBR（baseColor/metallic/roughness/alphaMode/doubleSided）；`textures`：引用 + `colorSpace` + 边长；`buffers`：外部引用 + `byteLength` + `sha256` + Draco/meshopt 标志。
- `labels`：锚点、billboard、避让/引线参数；文字内容可放 `g3d`（场景语义），UI 文案不放。
- `provenance`（AI 生成时）：`prompt`、`modelVersion`、`inputHash`、`cameraDiff` 可选；便于回溯，不保证可复现。
- 明确**不放**：实例 `camera/transform/visible/autoRotateOverride/lock/dim/layerRole`、`bookmarkPosterKey/lastFrameKey`、`versionRef`、UI 选中态、评论、作者/时间。
- 兼容：`formatVersion` 语义化；未知字段忽略；迁移函数按 `pipelineVersion`；缓存 key = `pipelineVersion + sourceHash + params`，不可变。
- 安全：不可信 GLB/GLTF 必须校验 JSON schema、buffer 长度、解压炸弹、节点/贴图上限、外部 URI allowlist；`g3d` 不执行脚本；分享 manifest 有总大小/解压上限。
- 大小：输出 `g3d` ≤8MB 舒适、8–20MB 降级、>20MB 拒绝；JSON 本体建议 ≤1MB；大 buffer 外置；单贴图 ≤1024 舒适/2048 硬；KTX2 P1。
- 导入：GLB/GLTF 优先；STL/OBJ 次之，STL 给默认材质 + 轮廓；非专用格式允许一次预处理；预处理两段式（<100ms 粗判/<1s 细判）；可取消；源文件只做 warning/timeout，硬闸门看预计输出。
- 版本：`g3d` 资产版本与画布实例版本分开；AI 编辑 COW 派生 `assetVersion`；`refCount` 含 undo/剪贴板；内容寻址去重；文档只留当前 + 最近 3 版指针；版本缓存是磁盘配额，不计入运行峰值。
- 不建议：把 `recommendedCamera` 当“唯一正确视角”；把 poster 塞进 `g3d`；把实例状态回写 `g3d`；为每个 overlay 复制一份 asset；用整份 `g3d` 做版本。

## 8. 一句话收口

**两种身份要的都不是“3D”，是“两次打开还是同一个东西，并且能把它交出去”。** 轻量侧要卡面 + 首帧 + 能转 + 存得下；开发者要相机 + 实例态 + 生命周期 + 峰值预算。任何一条断了，产品就退回一张截图；而截图不需要 `g3d`。
